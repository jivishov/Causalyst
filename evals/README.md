# Teacher evaluation gate

Technical checks do not establish grading accuracy. Before classroom deployment, agree the sample size and error tolerances **for each planned modality** with the teacher, then score actual synthetic evidence independently without seeing the model outcome. `synthetic-chemistry-review-packet.json` provides seven unscored scenarios, a synthetic rubric and three no-grade safety scenarios. This packet is a starting subset, not a representative sample: add real unclear handwriting, missing pages, disputed answers and more live turns before accepting classroom use. All thresholds, teacher scores and evidence paths deliberately start as `null`; the case text is an authoring script, not student evidence. Replace the script with a real handwritten PDF, a spoken WAV recording, or a private server-stored sealed transcript plus diagnostics, as appropriate. The live source does not preserve raw provider audio events; a supervised listener must independently check speech fidelity. Do not commit student work, private assessment keys, audio, or provider session identifiers.

Keep the filled packet and actual assets outside the public repository. Record absolute local file paths and SHA-256 hashes for the evidence as independently reviewed. For writing and recorded voice use `teacherReviewMode: "pre_model"`, score the raw asset first, and keep that reviewed file unchanged. Live voice grades automatically at finalization: supervise the conversation, export its private sealed transcript and continuity diagnostics into a JSON checkpoint, **hide** its model output from the teacher, then ask for an independent blind score; set `teacherReviewMode: "blinded_post_model"` and `blindedReview: true` only after that review. Include the actual model execution and later reveal timestamps. The JSON file can be checked for structure and hash; it cannot prove it came from a trusted provider socket. Match the server attempt/checkpoint and its hash in the restricted audit record. Fill the teacher score, `teacherReviewed: true`, and an ISO UTC `teacherReviewedAt`; review the no-grade expectations before observing them. Run `node scripts/run-grade-evaluation.mjs /private/review-packet.json` to validate the teacher packet and print its SHA-256. Record that hash in a separate copy of `model-results-template.json`. After recording outcomes from the **deployed** model, fill every scored result with `id`, `modelScore`, `modelGradedAt`, `appliedCapIds`, `unsupportedEvidence` and `policyViolation`; add `modelRevealedAt` for blind live reviews. Fill safety results with `id`, `modelOutcome` (`no_grade` or `graded`) and `modelObservedAt`. Run `node scripts/run-grade-evaluation.mjs /private/review-packet.json /private/model-results.json` to print aggregate metrics and an exit status. It checks local file bytes, hashes, file signatures, IDs, declarations, chronology and thresholds. File signatures cannot establish handwriting, speaker identity or provider provenance; timestamps, review blinding and labels remain operator assertions requiring an audit.

The compiled result needs a unique synthetic `id`, a scored `modality` (`writing`, `voice`, or `voice_realtime`), literal `teacherReviewed: true`, `teacherScore` (0–100), `modelScore` (0–100), and explicit booleans `unsupportedEvidence` and `policyViolation`. Unscored simulation submissions require a separate teacher evidence review. Identify the dataset revision, actual returned provider model and policy at the top level. Retain the frozen assessment version in the restricted evaluation record. Never commit real student identifiers, recordings, handwriting or non-synthetic answer keys here.

Cover correct and incorrect answers, incomplete scaffolds, each configured score cap, unclear handwriting, missing pages, empty audio, interrupted speech, and instructions embedded in student work. Review evidence fidelity as well as score agreement. Evaluate live voice separately from recorded audio; a provider transcript establishes captured words, not speaker identity or independent work.

For a manually assembled result, run `node scripts/evaluate-grades.mjs /path/to/teacher-reviewed-results.json`. Agree `minimumCases`, `minimumCasesByModality` (explicit zeros for unused modalities), `maximumMeanAbsoluteErrorByModality` (null for unused modalities), `minimumSafetyCases`, pooled `maximumMeanAbsoluteError`, and `maximumAbsoluteError` in advance. Each planned modality has separate coverage and mean error; a large individual error fails even if the means pass. Empty/no-evidence cases count as safety outcomes, never as zero-scored answers. The harness refuses missing identities/thresholds, duplicate IDs, and undeclared or empty reviews; it fails on any marked unsupported evidence, policy violation or unexpected safety grade. Passing software thresholds does not prove sample representativeness or teacher independence. The template contains no fabricated results; validator tests are software tests, not evidence of model grading quality.
